# التحليل الجنائي للفاتورة

> وثيقة مرجعية لملف `lib/features/invoices/invoice_pdf.dart`.
> **القاعدة الحاكمة:** الفاتورة مستند رسمي، ومطابقتها للأصل شرط وظيفي
> لا هدف جمالي. أي انزياح في موضع أو لون أو مقاس يجعلها مستنداً مختلفاً.

---

## 1. المرجع ونظام الإحداثيات

المصدر الأصلي: `bill.docx` و `bill.pdf` المرفوعان من صاحب النظام.

يعمل الملف على **شبكة مرجعية عرضها 1024 بكسل** (`_kRefW = 1024`)، وهي
عرض معاينة الأصل، وتُحوَّل إلى نقاط الطباعة عبر:

```dart
const _kPageWmm = 297.0;                        // A4 أفقي
const _kRefPxToPt = _kPageWmm / _kRefW * 72 / 25.4;
double _r(double refPx) => refPx * _kRefPxToPt;
```

**ارتفاع الصفحة مشتَقّ ولا يُكتب**: `_kPageHmm` يُحسب من `_Y.bottomBar`
أي من آخر عنصر في الصفحة. فلو أُضيف سطر أو كُبِّر خط، تكبر الصفحة معه
تلقائياً ولا يُقتطع شيء.

## 2. الألوان — مستخرجة لا مُقارَبة

لم تُقدَّر الألوان بالعين. استُخرجت من داخل `bill.docx`:

| العنصر | القيمة | كيف عُرفت |
|---|---|---|
| عنوان الفاتورة | `0xFF0000FF` | التسلسل `0000FF` ورد **31 مرة** في الملف |
| المبلغ المستحق | `0xFF0000FF` | نفس اللون — لا لون ثانٍ |
| خلفية ترويسة الجدول | `0xFFFCD5B4` | مستخرجة من تعريف تظليل الجدول |

```dart
static const titleNavy  = 0xFF0000FF;
static const amountBlue = titleNavy;   // لا لون منفصل — قصداً
static const headBg     = 0xFFFCD5B4;
```

> **درس:** في التعديل الأول قُدِّر أزرق المبلغ لوناً أفتح، فطلب صاحب
> النظام توحيدهما. الاستخراج من الملف يسبق الحسّ الجمالي.

## 3. الخطوط

| الخط | الدور | لماذا |
|---|---|---|
| **AmiriInvoice** | نص الفاتورة | خط نَسخي طباعي كلاسيكي مخصّص للمستندات الرسمية. يغطّي العربي + Arabic Presentation Forms-B (140 محرفاً) + الأرقام كاملةً |
| **TinosLatin** | احتياطي لاتيني | متوافق مترياً مع Times |

`_kFontBoost = 1.16` مُعامل تكبير عام طُبّق بطلب صاحب النظام، فصار
`_F.info = 16.4 × 1.16 = 19.02pt` (≈ **23.14px** مرجعية).

### تشكيل العربية في حزمة pdf

حزمة `pdf` لا تُشكّل العربية تلقائياً في كل المسارات. التشكيل يتم عبر
`arabic.convert()` (في `src/widgets/text.dart:958`) الذي يحوّل المحارف
إلى **Arabic Presentation Forms-B** (`U+FE70–U+FEFF`). ولهذا يجب أن
يغطّي الخط هذا النطاق، وإلا خرجت مربّعات فارغة.

## 4. أدوات القياس

### أ) مِسبار مقاييس الخط — القياس الحقيقي للحبر

يُقاس عرض النص الفعلي **داخل Dart** بنفس الخط والمقاس المستخدمين:

```dart
import 'package:pdf/pdf.dart';
// ignore: implementation_imports
import 'package:pdf/src/pdf/font/arabic.dart' as arabic;

final font = PdfTtfFont(PdfDocument(), boldByteData);
final m = font.stringMetrics(arabic.convert(s)) * fontSize;
final refPx = m.width / _kRefPxToPt;   // بالبكسل المرجعي
```

### ب) الفحص الجنائي من داخل ملف PDF — الأداة الحاسمة

```python
import pymupdf
d = pymupdf.open('/tmp/probe/out.pdf'); p = d[0]
sx = 1024.0 / p.rect.width            # نقاط → بكسل مرجعي
for b in p.get_text('rawdict')['blocks']:
    for l in b.get('lines', []):
        for s in l.get('spans', []):
            txt = ''.join(c['c'] for c in s['chars'])
            print(s['bbox'][0]*sx, s['bbox'][2]*sx, s['size']*sx, txt)
```

يُعطي هذا **صندوق كل محرف على حِدة** إضافةً إلى **مقاس الخط الفعلي**
لكل مقطع.

> ⚠️ **درس مُكلِف:** كان التشخيص الأول يعتمد على مسح البكسلات المعتمة
> في صورة PNG، فأعطى **نتيجة خاطئة**: دمج آثار حبر متجاورة فأبلغ أن
> الملصقات بعرض ‎177–194px‎ بينما عرضها الحقيقي ‎38–97px‎. مسح الصور
> يستدلّ على الحبر، وقراءة الـ PDF تقرأ الحقيقة. **لا تشخّص من صورة.**

## 5. عطل تداخل النقطتين واختفاء الأرقام — التشخيص والحل

### الشكوى

> «شوف التداخل هنا بين `:` والبقيه، وأيضاً بتختفي أشياء، ليش كان فيه شي
> يمسح الأرقام؟ حلّل الفاتورة بكسل بكسل. أشتي كل شي يكون **مرن** و
> **مضبوط**.»

### البنية المعطوبة

كانت كتلة البيانات ثلاثة صناديق **ثابتة العرض** موضوعة داخل
`pw.Stack`: `[الملصق ‎104px‎] [`:` عند ‎x216..230‎] [القيمة]`. وثلاثة
`pw.Positioned` أبناءَ `Stack` **لا يرى أيٌّ منها الآخر**.

### القياس الحقيقي عند `_F.info`

| الملصق | الصندوق | عرض الحبر | المتنفّس |
|---|---|---|---|
| اسم المشترك | 104 | 96.9 | 7.1 ✅ |
| رقم الفاتورة | 104 | 86.4 | 17.6 ✅ |
| **رقم الدورة** | **80** | **80.1** | **−0.1 ⚠️** |
| رقم العداد | 80 | 77.0 | 3.0 ⚠️ |

### الدليل القاطع من داخل ملف PDF

```
x 274.2..846.8   «0731ﺭﻗﻢ»        ← القيمة والملصق ككلمة واحدة ملتصقة (572px)
x 221.0..268.0   «ﺍﻟﺪﻭﺭﺓ:»        ← النقطتان ملتصقتان بالملصق
```

فتجاوز الملصق صندوقه ومرَّ **فوق** موضع النقطتين الثابت فغطّاها
(«اختفاء النقطتين»)، ولامسَ القيمة («مسح الأرقام»).

### الحل — تخطيط يقيس نفسه

استُبدل `pw.Stack` بـ `pw.Table` بثلاثة أعمدة:

```dart
columnWidths: const {
  0: pw.FlexColumnWidth(),      // القيمة — تأخذ ما تبقّى
  1: pw.IntrinsicColumnWidth(), // النقطتان — بعرض محرفها
  2: pw.IntrinsicColumnWidth(), // الملصق — بعرض أطول ملصق
},
```

`IntrinsicColumnWidth` (في `table.dart:171`) يُخطّط الابن بقيود غير
محدودة ويأخذ `child.box!.width`، ثم يأخذ `Table.layout` (`:358-430`)
الحدّ الأقصى لكل عمود عبر كل الصفوف ⇒ **عمود الملصق يأخذ عرض أطول
ملصق تلقائياً، والنقطتان تنتظمان في عمود واحد.** لا رقم ثابت واحد.

> 🔑 **تحذير جوهري:** `pw.Table` **لا يحترم `Directionality`**. لذا
> ترتيب الأعمدة في الكود **بصريّ من اليسار إلى اليمين**: القيمة، ثم
> النقطتان، ثم الملصق.

## 6. مصيدة `FittedBox` وارتفاع السطر — أهم درس في الملف

بعد إضافة `FittedBox(fit: scaleDown)` على القيمة لحمايتها من الاقتطاع
عند الأسماء الطويلة، **صغُرت كل القيم** من ‎23.14px‎ إلى ‎18.77px‎ بلا
سبب ظاهر.

### السبب

`FittedBox` يستدعي `constrainSizeAndAttemptToPreserveAspectRatio`
(في `geometry.dart:125`) الذي يُصغّر إذا تجاوز المحتوى العرض **أو
الارتفاع**. وكانت الخلية مُقيَّدة بـ `pw.SizedBox(height: 33px)` بينما
**ارتفاع سطر Amiri الطبيعي عند هذا المقاس ‎40.7px‎** ⇒ فظنّ أن النص لا
يسع رأسياً فصغّره.

### الحل

**لا يُثبَّت ارتفاع الخلية أبداً.** يُقاس ارتفاع السطر ويُشتقّ منه كل
شيء:

```dart
static const infoLineH = 40.7;               // ارتفاع سطر Amiri — مقيس
static double get infoRowPad =>
    ((_Y.infoStep - infoLineH) / 2).clamp(0.0, 100.0);

static const infoStep = _X.infoLineH + 3.3;  // = 44.0
```

مع `pw.Padding(vertical:)` و `TableCellVerticalAlignment.middle` ويُترك
الصف يقيس نفسه.
(القيمة الافتراضية للمحاذاة هي `top` — `table.dart:254`.)

## 7. قاعدة السلسلة — `_Y` مشتَقّة بالكامل

قيم `_Y.infoRowN` هي **أعلى الحبر** لا أسفله. فأي ثابت يُشتقّ من الصف
الأخير يجب أن يُضيف **ارتفاع السطر كاملاً** قبل حساب الفراغ:

```dart

static const tableBottom    = tableHeadBottom + 44.0;
```

> **درس:** أُغفلت `_X.infoLineH` مرةً، فوقع الخط السميك عند ‎y268‎ بينما
> بلغ حبر البيانات ‎y296‎ ⇒ مرَّ الخط **داخل النص**.

## 10. قواعد يجب التزامها في أي تعديل قادم

1. **لا رقم سحري.** كل قياس يُشتقّ من قياس آخر أو من قياس فعلي للخط.
2. **لا تُثبَّت ارتفاعات الخلايا.** يقيس الصف نفسه من سطر الخط.
3. **لا تشخيص من صورة.** الحقيقة تُقرأ من داخل ملف الـ PDF.
4. **`pw.Table` لا يحترم `Directionality`** — رتّب الأعمدة بصريّاً.
5. **اختبر الحالة القُصوى** (أسماء ومبالغ طويلة جداً) لا الحالة الطبيعية
   فقط.
6. **لا يُغيَّر شيء لم يُطلب** — الشعار والألوان والجدول والهوامش
   الجانبية تبقى كما هي.
